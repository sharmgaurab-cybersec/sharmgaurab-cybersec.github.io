04 / FIELD NOTES

Small lessons.
Better questions.

A few ideas I’m taking from the lab into how I think about systems and security.

001 / NMAPAn open port is a clue, not a verdict.+

My localhost scan showed six open TCP ports. That means services were listening on those ports during the scan. It doesn’t establish that they were vulnerable or reachable from the internet.

In a basic scan, Nmap’s service name can come from its port database. Version detection with nmap -sV 127.0.0.1 probes the service to gather more information. I still need to verify the software, configuration, and exposure before drawing a security conclusion.

Reference: Nmap service and version detection
002 / NETWORKINGHost discovery and port scanning answer different questions.+

Host discovery asks which systems respond. Port scanning asks which ports on a target are open, closed, or filtered.

nmap -sn performs host discovery without a port scan. A responding device is a starting point for learning about the network; it isn’t a statement about the device’s security.

Reference: Nmap host discovery
003 / IT OPERATIONSThe asset lifecycle is part of security.+

Security also depends on everyday handling: preparing a device correctly, knowing who it is assigned to, documenting its return, and following the right process when wiping it.

My deployment work gives me a practical reason to care about accurate records, user access, and secure decommissioning as I develop my cybersecurity skills.
